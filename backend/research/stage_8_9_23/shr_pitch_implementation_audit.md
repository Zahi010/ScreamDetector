# Subharmonic-to-Harmonic Ratio (SHR) and Pitch Tracking Implementation Audit

## Executive Summary

This audit examines the mathematical correctness, edge-case stability, and signal processing validity of the Subharmonic-to-Harmonic Ratio (SHR) and signal-conditioned pitch estimators used in Stages 8.9.21 and 8.9.22.

The audit was executed empirically by synthesizing benchmark test signals (pure sinusoids, biphonic period-doubled signals, 60 Hz mains hum, digital clipping, and near-silent hiss) and evaluating the existing implementation alongside a corrected, robust formulation.

### Summary of Audit Findings

| Component / Subsystem | Location | Mathematical Integrity | Vulnerability / Bug Identified | Severity |
|---|---|---|---|---|
| **SHR Decibel Scaling** | `subharmonic_features.py` | Valid | Uses $10 \log_{10}(\text{SHR} + 10^{-6})$. Correct power decibel formula. | Low / Benign |
| **Window Leakage in FFT** | `subharmonic_features.py` | Suboptimal | Uses Hann window with $N_{\text{FFT}} = 2048$. High side-lobe leakage (-32 dB) contaminates weak subharmonics. | Medium |
| **Mains Hum Contamination (60 Hz)** | `signal_conditioned_pitch.py` | Fragile | If $f_{\min} = 50 \text{ Hz}$, 50/60 Hz ground hum is tracked as a valid low pitch, artificially inflating pitch jitter. | Medium |
| **Near-Silence Adaptive Threshold Failure** | `signal_conditioned_pitch.py` (`compute_vocal_conditioned_pitch`) | **CRITICAL DEFECT** | `vocal_threshold = np.percentile(frame_rms, 60)` lacks an absolute minimum floor. ## 1. Deep Dive: The Near-Silence Adaptive Threshold Bug

### 1.1 Source File and Defective Function
- **File**: `backend/experiments/stage8_9_21_noise_robust_verification/src/feature_extraction/signal_conditioned_pitch.py`
- **Function**: `compute_vocal_conditioned_pitch(audio, sr)`
- **Defective Lines**:
```python
# Compute short-time RMS
frame_rms = librosa.feature.rms(y=audio, frame_length=frame_length, hop_length=hop_length)[0]
# Adaptive threshold: top 40% energy frames
vocal_threshold = np.percentile(frame_rms, 60)
high_energy_mask = frame_rms >= vocal_threshold
```

### 1.2 Identified Failure Mechanism
When an audio signal contains low-amplitude ambient noise or near-silence (e.g., peak amplitude $0.005$, RMS $0.001$):
1. `np.percentile(frame_rms, 60)` calculates a threshold of $0.001$.
2. The boolean mask `frame_rms >= vocal_threshold` selects the upper 40% of the noise frames ($N_{\text{frames}} \approx 40$).
3. Because the audio is unvoiced noise, librosa's pyin/yin algorithm fails to track pitch or returns voicing probability $< 0.10$.
4. The code checks:
```python
failed_high_energy_frames = np.sum((pitch_conf < 0.3) & high_energy_mask)
high_energy_pitch_failure_rate = failed_high_energy_frames / np.sum(high_energy_mask)
```
5. **Result**: `high_energy_pitch_failure_rate = 1.0` (100% failure)!
6. In `sddfr_classifier.py`, `he_pitch_fail > 0.35` triggers `is_confirmed_chaotic_scream = True`. **Pure background silence is confirmed as a violent human scream!**

### 1.3 Mathematical Formulation of the Correction
An absolute vocal floor $E_{\text{floor}}$ must gate the adaptive percentile:
$$\tau_{\text{vocal}} = \max\left(E_{\text{floor}}, \;\; P_{60}(\text{RMS})\right)$$
where $E_{\text{floor}} = 0.020$ (-34 dBFS).

If $\max(\text{RMS}) < E_{\text{floor}}$, the audio contains no significant vocal activity, and `high_energy_pitch_failure` must be explicitly defined as $0.0$ (or NaN) rather than $1.0$.

## 2. Deep Dive: SHR Formulation & Windowing

### 2.1 Mathematical Definition of SHR
Given an estimated fundamental frequency $f_0$, subharmonic energy resides at odd fractional multiples $f_{0}/2, 3f_{0}/2$:
$$\text{SHR} = \frac{\sum_{k=1}^K E\left((2k-1)\frac{f_0}{2}\right)}{\sum_{k=1}^K E(k f_0)}$$
In decibels:
$$\text{SHR}_{\text{dB}} = 10 \log_{10}\left(\text{SHR} + \epsilon\right)$$

### 2.2 FFT Side-Lobe Contamination
In the existing implementation:
- FFT Length: 2048 samples ($128 \text{ ms}$ at 16 kHz).
- Window: Hann.
- First side-lobe attenuation of Hann is only **-31.5 dB**. For high-amplitude vowels where harmonic peaks are 30–40 dB above the noise floor, side-lobe leakage spills into the $f_0/2$ bin, generating false subharmonic detections.

### 2.3 Proposed Signal Processing Enhancement
1. Replace Hann window with a **4-term Blackman-Harris window** (minimum side-lobe level: **-92 dB**), eliminating leakage into subharmonic bins.
2. Bandpass filter the signal ($100 \text{ Hz} - 4000 \text{ Hz}$) with an 8th-order Butterworth filter prior to SHR estimation to reject 50/60 Hz mains hum.
